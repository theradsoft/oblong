# oblong — project notes for Claude

Keyboard-driven window manager for Windows 11, modeled on Rectangle (macOS). Single
AutoHotkey v2 script: `oblong.ahk`. The owner runs it on their Windows machine; Claude
sessions usually cannot run AutoHotkey, so changes are written blind and tested by the
owner. Keep that in mind: be careful with AHK v2 syntax and say plainly that code is untested.

## History / status

Built iteratively in a chat, then moved here.
The settings GUI had not yet been tested on Windows when it was committed. Window sets
(newest part) were written blind and are also untested.

## What the owner wants (requirements gathered so far)

- Keyboard shortcuts first. Drag-to-snap is NOT wanted.
- Widths 1/4, 1/3, 1/2, 2/3, 3/4 at three heights: top half, bottom half, full height.
- Repeat presses cycle the window's *position* at the same size — never change the size.
- Custom cycles: one shortcut can walk through slots across heights in a chosen order.
- Direct-slot shortcuts (jump to a specific slot without cycling).
- Maximize height is liked. Larger/Smaller was explicitly removed.
- Custom shortcuts and sizes; gaps; move to other monitors.
- Number row OR numpad should both work.
- A settings GUI (first version now built).
- Window sets: save/recall named layouts. Decided design: per *current virtual desktop*
  (save and recall only see this desktop; never move windows between desktops — the
  official API can't do that for other processes' windows), matched by *app exe* not
  title, all of an app's windows go somewhere (extras stack on nearest spot, optional
  cascade), spots tied to a monitor by hardware ID with main-monitor fallback.

## Other files

- `oblong.ico` — tray/window icon (sizes 16-256), generated by `tools/make-icon.ps1`
  (System.Drawing; each size drawn natively and pixel-snapped). Regenerate rather than
  hand-edit.
- `docs/` — user documentation (installation, usage, compiling, known issues). Keep it in sync with
  behaviour changes.
- AutoHotkey v2 is installed on the owner's machine
  (`C:\Program Files\AutoHotkey\v2\AutoHotkey64.exe`): `/ErrorStdOut /Validate oblong.ahk`
  syntax-checks without running. Run behavioural tests from a scratch copy so the real
  `Oblong.ini`, hotkeys and startup shortcut aren't touched.

## File layout of oblong.ahk

1. Header + globals (`IniFile`, `StartupLnk`, `IconFile`, `MAXCOLS := 12`,
   `TypeNames`/`TypeActions`, runtime state). `TraySetIcon(oblong.ico)` runs before any
   GUI so windows inherit it; not frozen, so suspend still shows AHK's "S" icon.
   `SetStartup()` gives the startup shortcut the same icon. Auto-execute section calls `LoadConfig()` then `ApplyHotkeys()` and
   builds the tray menu (Settings... is the default/double-click item).
2. CONFIG: `DefaultBindings()`, `LoadConfig()`, `SaveConfig()`, `ApplyHotkeys()`,
   `ExpandKeys()` (adds numpad twins for digit hotkeys, NumLock on and off names),
   `PrettyKey()`, `FriendlyAction()`, `SetStartup()`.
3. SETTINGS WINDOW: `OpenSettings()` (ListView of bindings + settings group), edits a
   working copy `WorkBindings`; `SaveSettings()` writes INI and re-applies hotkeys live.
4. SHORTCUT EDITOR: `EditBinding(idx, prefillAction)` modal dialog. Global `Ed` holds its
   state. Key recorder uses `InputHook` with `{All}` "NS" and `Suspend(true)` while
   recording. Layout picker: 3 rows (Top/Bottom/Full) x `MAXCOLS` pre-created buttons,
   moved/shown in `RefreshEditor()`; labels show cycle order (#1,#5...).
5. WINDOW MOVING: `DoAction()`, `FractionRects()`, `ParseSlots()`, `ColumnPositions()`,
   `FracToRect()`, visible-rect helpers, monitor helpers (`GetMonitors(detail)` adds
   origin, primary flag, hardware ID via `MonitorHwId()`, order), `Remember()`.
6. WINDOW SETS: `SaveSet()`, `RecallSet()`, `LoadSet()`, `ListAppWindows()` /
   `IsAppWindow()` (taskbar-style windows, skips cloaked = other desktops, minimized,
   our own), `AppExe()` (resolves Store apps out of ApplicationFrameHost),
   `FindMonitor()`, `AssignWindows()` (greedy nearest spot, then extras to nearest),
   `PlaceStack()`, `WriteSet()` (writes spots, keeps the set's options). Tray submenu
   `SetsMenu` + manager window `OpenSetsManager()` (global `SetsGui`/`SC`). Set editor
   `EditSetSpots()` (global `SE`, working copy `SE.Spots`) and spot editor `EditSpot()`
   (global `SPE`) edit app, monitor, maximized and position in percent. Editor monitor
   lists come from `MonitorsForEditor()`, which restores the thread's DPI context so GUIs
   aren't affected. `DoAction()` routes `SaveSet`/`RecallSet` before needing a window;
   with no name it opens `PickSet("Save"|"Recall")` (global `Picker`, always-on-top,
   Enter/Esc, preselects `LastSetName`, which `SaveSet`/`RecallSet` update). The picker
   closes before saving/recalling so it's never in the way.

## Action grammar (stored in INI, built by the editor)

    <num>/<den> <step> [<step> ...] [down|across]
    step := Top | Bottom | Full  [@N]

- Bare height = every column at that height, left to right.
- `@N` = single column N (clamped).
- `down` interleaves column by column; default `across` finishes each step in order.
- Columns for width w (`ColumnPositions`): tile from the left while it fits, then add a
  right-aligned slot if needed (2/3 -> 0, 1/3; 3/4 -> 0, 1/4).
- Other actions: Maximize, AlmostMaximize, MaximizeHeight, Center, Restore,
  NextDisplay, PrevDisplay, `SaveSet [<name>]`, `RecallSet [<name>]` (no name = ask).
- AHK gotcha hit here: don't name variables after built-in functions (`isSet`, `type`
  failed `/Validate`).

Cycling: if the same action is triggered on the same window and the window still matches
the rect we last set (`RectsClose`, 8 px), advance the index; otherwise start at slot 1.

## Config file (Oblong.ini, next to the script, gitignored)

    [Settings]
    Gap=0
    AlmostMaxSize=0.9
    CycleOnRepeat=1
    NumpadToo=1
    [Hotkeys]
    1=^!1|1/4 Top
    ...

    [Set:Coding]
    Cascade=0
    MissingMonitor=main
    1=chrome.exe|DEL41A8|1920,0|2|0.0000,0.0000,0.6667,1.0000|0

Hotkey lines are `N=<ahk hotkey>|<action>`, split on the LAST `|` (hotkeys may contain `=`).
Set spot lines are `exe|hwid|monLeft,monTop|order|fx,fy,fw,fh|maximized`, fractions of
the monitor's work area. Set names: `^\w[\w .\-]*$`, max 40 chars.

## Technical decisions worth keeping

- Per-monitor DPI awareness set at the start of every action
  (`SetThreadDpiAwarenessContext(-4)`).
- Positions use the DWM extended frame bounds (visible frame) and compensate for Win10/11
  invisible borders; `SetVisibleRect` does two passes to handle DPI change across monitors.
- Monitors are sorted left-to-right then top-to-bottom for next/prev display; moving keeps
  the window's relative position/size and re-maximizes if it was maximized.
- Gap model: inset work area by gap/2, then inset each cell by gap/2 (edges and between
  windows both = gap).

## Known caveats

- Elevated windows can't be moved unless the script runs as admin.
- Shift+numpad digits with NumLock on don't arrive as shifted digits, so Shift-based
  numpad shortcuts won't fire; suggest Win instead of Shift for those.
- Ctrl+Alt+arrows can collide with Intel graphics rotation hotkeys.
- Overriding Windows' own Win+arrow snapping works by binding those keys in oblong.
- Moving the script breaks the startup shortcut (it only gets created if missing).
